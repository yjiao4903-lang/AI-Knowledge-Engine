# 个人深度学习平台：开发任务与交接计划 V1.0

日期：2026-09-05（Asia/Shanghai）  
状态：规划完成，全部功能任务待开发；不代表代码、真实 UI 或外部研究已经通过验收。  
需求：[产品需求 V1.0](DEEP_LEARNING_PLATFORM_REQUIREMENTS.md)。

## 1. 新开发窗口先做什么

1. 读本计划、产品需求、CURRENT_STATE、INTEGRATION_CONTRACT_V2。
2. 检查工作区修改和远端当前代码。2026-09-05 规划时本地工作目录落后于已阅读的远端；不要重复开发远端已有 Launcher 与 Task Center 调整，不覆盖用户修改。
3. 默认从 DL-00 开始，完成主题与接口核对后再进入功能开发。
4. 本轮交付只做单主题纵向闭环，不把任务扩大成全库自动建图或通用代理平台。
5. 每次交接更新本文件状态表、具体证据、未验证项和下一任务；CURRENT_STATE 只登记实际实现。

未获新用户指令时，本计划本身不授权启动任务。文档中的技术名、候选字段和文件名均需在实施时验证。

## 2. 优先级与依赖

P0 = 首版闭环必需；P1 = 主闭环通过后增强。DL-01 是可靠性门槛，可在其实现期间推进不依赖它的契约/页面工作，但不能跳过真实验收。

|---|---|---|---|---|---|
| DL-00 | P0 | 试点与契约确认 | 无 | KE + 真实 Cognition 只读核对 | TODO |
| DL-01 | P0 | 基础运行与全文路径解耦 | DL-00 | KE runtime / retrieval | TODO |
| DL-02 | P0 | 主题研究档案与方向 | DL-00 | Cognition 主界面 + KE 派生读取 | TODO |
| DL-03 | P0 | 研究上下文包与认知选择 | DL-02 | KE TaskPack + 主界面 | TODO |
| DL-04 | P0 | 报告增量与关系候选 | DL-03 | KE + External Worker | TODO |
| DL-05 | P0 | 缺口发现与选题卡 | DL-04 | KE 规划 + 主界面 | TODO |
| DL-06 | P0 | 研究回流与对象修订候选 | DL-03、DL-04 | KE + Cognition staging/preview | TODO |

用户后续指定的紧急修复优先。除此之外，新模型、检索参数调优、通用 UI 美化与 Scheduler 扩建置于主线之后。

## 3. 任务卡

### DL-00：试点、真实接口与存储决策

目标：避免文档驱动出第二套正式知识库或虚构接口。

工作：

- 核对 `backend/app/contracts/cognition.py`、`integration/`、TaskPack schema 与真实 Cognition 项目。
- 确认 Topic、Question、Judgment、Proposal 可读字段、稳定 ID、版本及正式修订预览能力。
- 记录各逻辑对象映射、候选存储位置、派生主题状态更新方式、API 能力差距与备份范围。
- 确认一个试点主题及材料范围。没有用户选择时可用隔离的合成材料完成契约验证；不得把示例写入用户正式研究方向。
- 确定新增任务输入/输出版本与旧 Worker 的兼容策略；新端点只有在契约明确后实施。

交付：在本文件“决策记录”填入对象/API/存储映射、试点与技术边界；如必须改集成契约，提交可审阅的契约变更。

验收：每项必需读写操作指向真实接口或明确缺口；正式写入者唯一；无新依赖的默认方案清楚；跨项目改动与测试位置清楚。

阻塞处理：真实 Cognition 不可读或必要接口不存在时，列出缺口并继续 KE 独立契约工作；跨系统闭环不得标 PASS。

### DL-01：无模型基础运行

目标：基础知识与研究规划不因语义服务不可用而消失。

定位：`backend/app/main.py`、`api/search.py`、`inference/manager.py`、`indexing/pipeline.py`、`cognition/pipeline.py`。

工作：统一前后端 lexical / rerank=false 默认；推理进程延迟初始化；全文索引与向量维护分开；Cognition 全文读取与 Qdrant 管线初始化分开；显示能力状态与实际检索模式。

验收：无 Qdrant、没有可用模型文件时，真实应用启动、报告与认知全文检索、证据读取、规划元数据保存和 TaskPack 创建可用；新增/更新材料能进入全文索引；显式语义请求返回可解释状态；基础路径不启动模型进程。

验证：保留现有检索回归，增加无模型真实进程 smoke；仅替换 InferenceManager 的测试不能作为此任务通过证据。不得通过删除实际模型或生产数据制造测试条件，使用隔离配置。

### DL-02：主题研究档案

目标：用户从问题与认识进入研究，而不是只能从搜索开始。

工作：

- 在 Cognition 现有产品壳增加主题研究档案，优先复用页面与正式对象。
- 展示方向、范围、问题、当前判断、证据、更新时间、待处理候选。
- 提供方向确认与草稿问题入口；正式内容走现有写入流程。
- KE 提供可重建派生读取；没有数据时提供真实空状态，不生成示例冒充积累。
- 主题摘要带来源版本和时间；来源变化时标记待刷新，保留上次研究快照。

验收：一个主题的各区块可回到原对象/证据；浏览器重启后规划状态保留；正式对象改名不丢失关联；没有语义能力时仍可浏览和手工组织。

验证：主题聚合契约、空主题/失效引用/旧版本场景、真实页面读取路径。不得只交付静态图谱或手写演示 JSON。

### DL-03：已有认知进入任务与上下文包

目标：没有历史对话的窗口，也能接续研究。

定位：`frontend/src/pages/SearchPage.tsx`、`backend/app/contracts/cognition.py`、`taskpack/builder.py`、`taskpack/schemas.py`、Worker 模板；实际主入口优先接入 Cognition。

工作：

- 提供已有问题/判断选择器，移除主路径固定空上下文的断点；保留有意不选的合法路径。
- 把用户方向、主题状态、本次任务组合成可读 brief 与结构化快照。
- 服务端解析稳定 ID 并读取权威内容，不把浏览器 excerpt 视为正式事实。
- 明确研究范围、已知反证、外部检索许可、输出要求与重复研究排除项。
- 限制包体预算，显示遗漏/过期/失效引用，导出清单排除无关私人内容。
- 保留旧包读取与旧任务类型；新增文件仅在协议版本支持时使用。

验收：任务包确实含所选认知与主题信息；复制到不同目录仍可理解；旧包继续可读；超限不静默丢失关键上下文；新窗口只读包能复述目标、现状、缺口、范围和交付要求。

验证：服务端对象解析、失效 ID/版本、体量上限、旧协议回归；记录一次真实新窗口盲读结果。此任务可先使用手工选题，不依赖自动推荐完成。

### DL-04：报告增量与关系候选

目标：一份新报告进入后，主题认识发生可审阅的增量变化。

工作：

- 基于 DL-03 创建显式报告增量任务，外部 Worker 返回分类结果与关系候选。
- 关联报告片段、现有判断/问题与关系两端；支持新增、补证、冲突、限制、重复和无法判断。
- 区分关联/类比/因果假设；检查引用存在性，语义是否成立留给审阅。
- 提供接受、拒绝、延后入口；人工确认的正式关系经 Cognition 接口处理。
- 持久保存候选与拒绝理由；同一输入重试不重复生成一组待审记录。

验收：含一组有依据关系、一组证据不足关系、一份重复报告的样本；缺乏证据时可返回无法判断；拒绝不改变正式知识；后续新证据允许重新提出但解释变化。

验证：结构/引用/状态与重试测试，加人工逐项检查。引用格式正确不能代替关系成立的判断。

### DL-05：可解释选题卡

目标：从主题缺口生成少量可执行选题，而不是热门标题列表。

工作：

- 从冲突、机制缺口、未验证前提、条件变化等输入生成候选。
- 落实需求 FR-04 必填字段，默认每次不超过 5 个；允许零候选。
- 用主题/问题/任务历史发现重复，疑似相同由用户决定，不只按标题判断。
- 展示主线关联、增量、证据可得性、成本档位与排序理由。
- 支持选择、拒绝、延后；选中后接 DL-03 生成 TaskPack，重复操作复用关联任务。

验收：每题可回溯触发证据；选择后有真实任务；重复题可识别；无有效缺口时不凑数；推荐不自动启动 Worker，不改变长期方向。

验证：缺口输入到卡片的确定性契约、重复/空候选/错误引用、选题到任务的重试；用户评审研究价值。排序质量未经评审不得声称“智能推荐有效”。

### DL-06：成果回流与原对象变化

目标：外部研究回来后推进原问题，避免只有新增条目。

定位：`integration/proposals.py`、`integration/cognition_gateway.py`、`api/research_os.py`、`taskpack/` 与 Cognition staging / preview。

工作：

- 结果指向原问题、现有判断和主题，表达新建、补证、修订、建议撤回、问题推进、关系变化。
- 预览旧表述、新表述、理由和证据；正式确认仍在 Cognition。
- 目标版本变化时重新读取并提示冲突；不自动覆盖新判断。
- 分别显示 Worker 完成、校验通过、候选已发送、用户已确认、主题已刷新。
- 从 Cognition 回读确认实际正式结果，保存 TaskPack—候选—正式对象关联。

验收：至少一次对已有判断的真实修订闭环；旧版本与理由保留；拒绝不改变原对象；过期对象冲突可处理；新任务带入更新后的认识。

验证：候选映射和版本冲突测试，真实 Preview/Apply 与回读；重复发布不产生重复候选。若 Cognition 不支持所需能力，标明跨项目阻塞，禁止 KE 直接写 Markdown 代替。

### DL-07：单主题真实验收

目标：验证端到端产品价值，决定是否扩展规模。

工作：按产品需求第 8 节执行完整场景；选用隔离数据，真实正式写入演练需要明确的试点范围，不修改其他主题。

交付：在下方“验证记录”登记环境、主题/样本范围、实际任务、每步结果、界面证据位置、用户意见、失败原因与残留问题。

通过条件：DL-01 的无模型基础路径与真实研究闭环均有证据；用户确认至少一个选题有价值、一次成果确实推进原问题。用户尚未评审时保持 CONDITIONAL，不能用模型自评替代。

停止条件：主要输出重复、联系缺乏证据、上下文误导外部窗口、正式结果无法回读。失败先修最短链路，不启动全库处理。

### DL-08：知识复用与理解记录（P1）

工作：记录证据/判断参与过的任务，显示未解决问题回访；提供个人机制解释、失效条件与迁移案例草稿。复用次数不作为真假或掌握程度的代理。

验收：可以从判断找回研究来源和后续使用；用户原文保留；学习提示不会自动提升正式判断或输出未经验证的能力评分。

### DL-09：多主题发现与渐进扩展（P1）

工作：基于单主题真实结果逐步扩到第二个主题，提出跨主题机制/类比候选；保留探索理由与边界。先分析采纳/拒绝/重复原因，再讨论推荐排序改进。

验收：跨主题关系有来源与适用条件；用户能拒绝不相关联系；重复和无依据关系可观察；扩展不会损坏首版闭环。无需预先承诺在线学习、全库重分析或自动调度。

## 4. 统一完成定义

每项功能任务分别记录：

- STATIC：代码和契约已检查。
- TESTED：实际执行了相称的测试，记录命令、结果、日期。
- HTTP VERIFIED：实际服务接口行为已验证。
- UI VERIFIED：真实界面路径已操作，不能用构建成功代替。
- HUMAN REVIEWED：用户/指定审阅者评估关系、选题或研究价值。

这些是证据标签，不是强制所有任务运行相同测试。纯文档修改只做链接、内容与变更检查；算法改动使用对应回归；跨系统闭环必须有真实 UI/接口证据。

任务状态使用 TODO / IN_PROGRESS / BLOCKED / DONE。DONE 需要满足该任务全部验收；部分通过记录到验证表，不提前打勾。BLOCKED 写清具体外部条件和可继续的独立工作。

不得删除或改写原始报告；不得把测试候选自动提升为正式对象；提交/推送/部署遵从当次用户授权，不由本计划自动授权。

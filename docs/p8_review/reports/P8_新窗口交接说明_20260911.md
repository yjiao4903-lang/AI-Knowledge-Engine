## 6. 踩坑清单（**每条都真实发生过，务必遵守**）

### 6.1 进度指标会被表象欺骗（最严重）
曾出现"`chunks` 持续增长、进程存活、`indexed_at` 命中 207 篇，但**净入库仅 +4**"——重复索引旧文档造成的假进度。**唯一可信指标是 `sync`。** 曾因误判损失 8 小时。

### 6.2 `state.done` 只是缓存，scan 才是权威
曾出现 `scan NEW=71` 但 `todo=0`——71 篇被 state 白名单吞掉，永远跳过。现逻辑：**scan 报 NEW/MODIFIED 的路径一律清除其 done 标记**。

### 6.3 引擎 docid_policy 跨批次不消歧（引擎缺陷，只能绕开）
`app/indexing/docid_policy.py:146` 的 `__sha256[:8]` 消歧**只在同批候选内生效**。新文件 `report_code` 与库内 id 相同但内容不同时 → 分配重复 doc_id → INSERT 撞 UNIQUE → **引擎静默吞掉、整批回滚**。
→ 我们的做法：在**自有 markdown front matter** 上预消歧（本轮 157 + 15 篇）。

### 6.4 scanner 以"当前 roots"判 DELETED（可跨语料误删）
`scanner.py` 的 manifest 取自 **DB 全表**，凡不在当前配置 roots 上的文档一律判 `DELETED`。
→ 历史上 D 盘 M 系列就是这样被删空的（`config.yaml` 原注释记录了"暂摘"）。
→ **铁律：任何 roots 变更前，先只读扫一遍确认 `DELETED=0`；生产配置必须保持合集 roots。**

### 6.5 `apply_scan` 静默吞失败
引擎对内部失败自行记录并继续、**不抛异常**。→ 调用方必须**逐文档按 sha 复核**才算成功，不能信任返回值/退出码。

### 6.6 Qdrant 不可达时，引擎 exit 0 且无 stderr
`IndexPipeline` 构造阶段直接退出，表象是"静默 Δ0"。→ **任何索引/回归前先 `curl http://127.0.0.1:16333/collections` 预检**（`run_overnight.py` 已内置 preflight）。

### 6.7 批次在途 ≠ 停滞
单批 15 篇约 6~20 分钟。审计若按固定间隔看 `sync` 会把正常批次误判为停滞。→ 现机制：**批次开始也写心跳**，审计据此判 `INFLIGHT` 不计停滞。

### 6.8 停机止血后不得自动重启
曾出现"STALL 停 → 下一 tick 自动重启 → 再 STALL"死循环。→ 现加**闩锁**，需人工介入。

### 6.9 Windows/WSL 专有坑（都踩过）
- `os.kill(pid, 0)` 在 Windows 上等于 **TerminateProcess（会杀进程）**——探针禁用。
- `tasklist` 在 `pythonw` 进程下会误判——用 `Get-CimInstance Win32_Process`。
- PowerShell 进程探测会**匹配到自己的命令行**——需排除 `$PID`。
- **WSL 排除 TCP 端口段 6309–6408 吞掉了 6333** → Qdrant host 端口已改 **16333**（compose + config 两处）。

### 6.10 上线前必须冒烟测试
`py_compile` **查不出运行时 `NameError`**。本窗口两次因此翻车（一次导致托管器首 tick 崩溃、apply_loop 成孤儿）。→ 托管类脚本上线前先跑 `--once` 或单批。

### 6.11 收尾前必须确认没有索引进程
索引与 backend 同时写 catalog 会冲突。→ `finish_closeout.py` 已加锁（检测 `apply_loop`/`ingest_audit`/`golden_index` 进程即拒跑）。

### 6.12 归档语料不能用 `apply_loop` 直接跑
scanner 把 7,227 个文件全报 NEW，但引擎排除规则在索引计划阶段才生效；`apply_loop` 会把 ~7,011 个被排除文件当"入库失败"，**失败数超 60 即中止本轮**。→ 必须用 `golden_index.py`（先预过滤）。

### 6.13 别轻易启动哨兵
`sentinel.py` 是链守护，判定链未完成时会重新拉起索引，与 backend 抢写。→ 默认不启动。

### 6.14 台账单点
`_meta/进度状态.md` 是唯一台账。**每完成一个工作包必须更新它**，避免多窗口各自维护状态。

### 7.3 写 `pipeline/p8_trace.py`（**本工作包的核心**）

**只读、不改引擎**。利用引擎现成接口（已核实可用）：

- `SearchEngine.search(query, mode=..., filters={document_ids,domains,evidence_levels,content_types,date_from,date_to}, debug=True, rerank=...)`
  - `mode` 可逐臂调用（`terms`/`trigram`/`lexical`/`dense`/`hybrid`/...）
  - `filters` 支持**召回前 pre-filter**（dense 走 Qdrant filter、lexical 走 FTS filter）→ 隔离实验无需重建索引
  - `debug=True` 返回各召回路排名；`rerank_trace` 给出重排前后
- 需要精确 gold 名次时，直接调用 `DenseRetriever.search / LexicalSearcher.search`（返回完整 k 列表）自行组合

**每题必须输出**（规范 §6.1）：`dense/terms/trigram 名次 → fused 名次 → rerank 输入位次/输出名次 → final 名次`；
**必须计算**（规范 §6.2）：`Dense Recall@50`、`Lexical Recall@50`、`Union Recall@50`、`Fusion Recall@30`、`Fusion Recall@50`、`Rerank Recall@K`。

## 8. 供评审/新窗口注意的两个技术事实（本窗口核实）

### 8.1 `sections.heading` 跨 source_type 质量不均 → 新题集金标不能用 heading 锚定

```
旗舰(M系列)        ："第 1 章 大分流前夜：18 世纪欧亚核心区的双福利轴审计"   ← 真实语义标题
公众号/日报(OCR)   ："Groq 推理通证经济学：速度，但代价几何？ --- Groq Inference Tokenomics: Speed," ← 自动截断
                     "元信息" / "图表（p2 OCR）" / "图表（p5 OCR）"            ← 占位标题
配图资料           ："配图资料：即时讨论___Kimi_短评" / "元信息" / "配图1"      ← 占位标题
```

→ 旧 50 题用 `heading_contains` 只对旗舰语料成立；**新 Development/Holdout 题集必须固化 `section_id`/`chunk_id` 或锚定正文片段**，否则会大量误判失败。

### 8.2 占位标题章节是"混库竞争"的具体可测机制

日报/OCR 类文档产生大量低信息量碎片（`元信息`/`图表（pN OCR）`/`配图N`），天然充当跨文档干扰项。这正是 §7.5 要量化、Q4 要回答的对象。

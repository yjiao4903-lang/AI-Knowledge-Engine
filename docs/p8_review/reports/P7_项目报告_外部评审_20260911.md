**本轮成果（事实）**

- 修复 4 个工程机制缺陷（详见 §6.3），其中 1 个曾导致 **8 小时静默空转、净入库 0**

**核心问题（事实）**

> **Golden 检索回归未通过门线：`gate_pass = false`。**
> `hybrid_rerank` Hit@5 **0.82**（门线 0.90）、MRR **0.640**（0.75）、NDCG **0.678**（0.80）；

**失败构成（9/50）**

| 类型 | 数量 | 含义 |
|---|---|---|
| `LOW_DENSE_RANK` | 5 | 金标章节**已被召回**（在候选池内），但最终排名被挤出前 5 |
| `NO_RECALL` | 2 | 金标章节未进入候选池（召回失败） |
| `BAD_FUSION` | 1 | 已召回但融合阶段未排出 |
| `BEST_ARM_FAIL` | 1 | 所有臂均未命中 |

失败题目：`E02`(BAD_FUSION)、`S01`(BEST_ARM_FAIL)、`C01`/`C03`/`O02`/`R01`/`X01`(LOW_DENSE_RANK)、`W01`/`X03`(NO_RECALL)。

**我们的归因（供评审质证）**

1. 主要失效模式是**干扰项暴增导致的排序下滑**，而非索引缺失——金标 5/9 仍在候选池内、只是排名 6~10；`unresolved = 0` 说明答案位置全部解析成功。
2. 生产配置的候选深度有限：融合后仅 30 条、仅 24 条进入重排，最终取 10 条。**落在融合排名 25 名之后的金标根本没有被重排的机会**。
3. 门线原标定于 189 篇语料；本次语料规模为其 18.9 倍。**"未达旧门线"与"引擎退化"是两个不同命题**，需要评审帮助定性。

**需要评审回答的关键问题**

- Q1：该判为"检索质量回归（需调优）"还是"门线需随语料规模重新标定"？抑或两者并行？
- Q2：若调优，可接受的延迟预算是多少？当前 hybrid_rerank p95 = 1,411 ms，扩大候选深度会线性抬高（粗估翻倍候选 → ~2.5–3 s）。
- Q3：50 题的样本量是否足够支撑门线判定？（我们对参数扫描存在过拟合风险的判断是否有依据）
- Q4：2 例 `NO_RECALL` 是否可接受（归因于问题措辞与语料表述差异）？

### 6.2 引擎层缺陷（`D:\AI-Knowledge-Engine`，我们无权修改，仅记录并绕开）

**① `docid_policy` 跨批次不消歧 → 整批静默回滚**（影响最大）

- 机制：`app/indexing/docid_policy.py:146` 的 `__sha256[:8]` 消歧**只在同一批候选内生效**；当新文件的 `report_code` 与库内已有 doc_id 相同但内容不同（sha 不同）时**不消歧**，直接分配重复 doc_id → `INSERT` 违反 UNIQUE → 引擎**静默吞掉异常整批回滚**。
- 证据：本轮 157 篇因此永远无法入库；且表现为"`indexed_at` 命中 207 篇、净增仅 +4"的假进度。
- 我们的绕开方式：在**自有 markdown 的 front matter** 上按同一策略预消歧（`report_code → rc__sha8`，可回滚），未改引擎代码。

**② `scanner` 以"当前 roots"判定 DELETED → 可误删另一语料**

- 机制：`app/indexing/scanner.py` 的 manifest 取自 **DB 全表**，凡"不在当前配置 roots 磁盘上"的文档一律判 `DELETED`。因此**修改 roots 的配置会删掉另一批语料**。
- 证据：`D:\AI深度报告归档`（M01–M24 旗舰语料）当年正是这样被清空的；`config.yaml` 原注释亦记载该 root 被"暂摘"。
- 我们的规避：恢复 root 前**先做只读扫描验证 `DELETED=0`**；最终配置采用**合集 roots**（D 盘归档 + E 盘 9 个目录）。

**③ worker IPC 挂起**

- 机制：部分文档（历史上为 M10 区段）会挂起引擎 worker，无超时、无报错。
- 证据：当年归档 root 因此被摘除；本轮若用常规 worker 路径索引归档会重演。
- 我们的绕开方式：索引驱动改用**进程内 `TorchEmbeddingProvider`**（不经 worker IPC）。

**④ 静默失败模式（多处）**

- `apply_scan` 对内部失败自行记录并继续、不抛异常；调用方必须**逐文档按 sha 复核**才能发现漏索引。
- Qdrant 不可用时 `IndexPipeline` 构造阶段直接退出，**exit code 0 且无 stderr 外露**，表现为"静默 Δ0"（本轮实测）。
- 建议（供评审）：引擎侧为上述场景增加结构化错误返回与显式非零退出码。

## 7. 已知风险与不确定性

1. **Golden 判定依赖 50 题样本**：样本量偏小，参数优化存在过拟合风险；建议保留基线并记录每次实验。
2. **门线历史口径**：门线标定于 189 篇语料，直接用于 3,566 篇语料在方法论上不严谨（已如实标注）。
3. **延迟预算未知**：扩大候选深度提升命中率，但 p95 已 1,411 ms，产品可接受上限未定义。
4. **语料扩容的连带效应**：E 盘研报库以短篇日报/讨论帖为主，与 M 系列长篇旗舰报告混库检索，可能系统性稀释后者的排序（本轮失败模式与此一致）。
5. **硬件稳定性**：曾出现 Windows/ROCm 侧静默崩溃与一次非计划重启（22:15，致 2.5 小时空转）；已通过每 30 分钟巡检自动化兜住，但根因（驱动/PSU 瞬态）未闭环。
6. **引擎侧不可修改**：§6.2 的缺陷只能绕开，长期需引擎维护方修复。

## 8. 优化路径与建议（按性价比排序）

**A. 配置级（零代码、可回滚、可快速 A/B）**

| 参数 | 现值 | 建议试验 | 针对问题 |
|---|---|---|---|
| `rerank_k` | 24 | 40 / 50 | LOW_DENSE_RANK（最直接） |
| `fused_k` | 30 | 50 | 让更多候选获得重排机会 |
| `dense_k` / `fts_terms_k` | 50 | 100 | NO_RECALL |
| `fusion` 权重 | 1.0 / 0.9 / 0.7 | 多组 | 词法证据是否被向量淹没 |
| `parent_boost_sections_k` | 8 | 调参 | 同节多片段证据聚合 |

**关键便利**：Golden 回归单次仅需 **约 2 分钟**，且支持指定配置文件路径——可在 **E 盘生成配置副本**做参数扫描，**完全不修改 D 盘引擎**。

**B. 模型级（提升潜力最大）**：重排模型 `Qwen3-Reranker-0.6B` → 4B 版本（需下载模型、评估显存与延迟）。

**C. 语料级（代价最大）**：分块参数调整（需全量重索引 29.6 万片段，耗时以小时计），建议最后考虑。

## 附录 · 术语表

| 术语 | 含义 |
|---|---|
| doc_id | 引擎内文档主键，默认取 front matter 的 `report_code` |
| chunk | 文档切分后的检索单元（共 296,385 个） |
| sync | 真实入库数：根文件 path 在 catalog 且 sha256 一致的数量（唯一权威进度指标） |
| Hit@5 / MRR / NDCG | 前 5 命中率 / 首个正确答案排名倒数均值 / 加权排序质量 |
| Golden | 50 题手工校对答案的固定评测集（含答案所在章节与相关度分级） |
| 臂（arm） | 一种检索策略；7 臂并跑用于消融归因 |
| quarantine | 隔离区（超大文件、语言重复版），**不进引擎 roots** |
| EXCLUDED_DUPLICATE | 引擎规则：同 doc_id 且同 sha 的镜像副本，排除不索引 |

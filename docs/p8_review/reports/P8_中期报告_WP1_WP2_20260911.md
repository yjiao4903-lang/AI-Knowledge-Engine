## 0. 摘要（结论先行）

1. **主要瓶颈是「语料竞争」，不是召回、也不是候选深度。**
   同一批 50 题、同一金标，把检索域从全库 3,566 篇收窄到旗舰归档 187 篇：
   **Hit@5 0.82 → 0.90**、MRR 0.640 → 0.752、NDCG 0.678 → 0.789、NO_RECALL 2 → 0。
   题级候选存在率 union 0.96 → 1.00。→ **H1 成立**。

2. **候选深度不是瓶颈。** A 组（fused_k 30→60 / 重排 24→50）Hit@5 0.82→0.80/0.80/0.82，p95 1310→2348 ms（+79%），**触发规范 §9.1 停止规则**。→ **H2 不成立**。

3. **召回广度的边际收益不可用。** B 组（dense/terms 50→100）把 W01/X03 拉进候选池（union 存在率 0.96→1.00），但其融合名次为 117/195，远超 fused_k，进不了重排；Hit@5 反降至 0.80、p95 +46%。→ **H3 不成立（广度非有效杠杆）**。

4. **融合权重仅有小幅 Pareto 改善。** F2（0.9/1.0/0.8）Hit@5 0.82→0.84、NDCG 0.678→0.688、p95 略降；但仍远达不到 0.90。→ **H4 部分成立（方向对、量级小）**。

5. **任何单参数杠杆最多 +0.02 Hit@5；只有语料分层/隔离能到 0.90。**
   → P8 的架构性答案指向 **Corpus Routing / 分层检索（P8-5）**；剩余排序问题（重排/chunk）是次要杠杆。

6. **重大语料发现（H5）**：外资研报 tier（220,635 chunks，占全库 **74%**）的章节标题在**抽取阶段丢失**，**99.9% chunk 落在占位标题下**（`元信息` 覆盖 155,616 chunks）。抽样源 markdown 24,133 行仅 2 个 `#` 标题。这不是引擎解析错误，修复需重抽取（触及红线，需决策）。

## 4. 结论与路线建议

1. **不要继续扩候选池**（§9.1 已触发）。
2. **P8 的下一杠杆是分层/竞争治理**，而非继续调单参数：
   - 离线验证 **Corpus Routing**（flagship / formal_report / daily-discussion 分池 → 各取 TopK → 合并重排），规范 §12；
   - 这与 H1 的直接证据一致：高价值旗舰内容在混库中被短篇/低标题质量语料稀释。
3. **次要杠杆**：重排输入质量（尤其外资研报 chunk 的 `Section` 字段因标题丢失而退化为 `元信息`，可能同时损害重排与竞争）与 chunk 粒度（flagship p50 318 字偏短）。
4. **F2 权重可作为低风险的小改善保留观察**，但不足以取代门线重标定。
